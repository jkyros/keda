# Kafka Scaler Kerberos Authentication Example

This directory contains a complete working example of using KEDA's Kafka scaler with Kerberos (GSSAPI) authentication.

## Overview

This example demonstrates:
- Kerberos KDC deployment
- Kafka broker configured with SASL/GSSAPI authentication
- KEDA ScaledObject with Kerberos authentication
- Test consumer deployment that scales based on Kafka lag

## Quick Start

### 1. Deploy the KDC and Kafka

```bash
kubectl create namespace kafka-kerberos-demo
kubectl apply -f 01-kdc-deployment.yaml
kubectl apply -f 02-kafka-deployment.yaml
```

Wait for the KDC and Kafka to be ready:

```bash
kubectl wait --for=condition=ready pod -l app=kdc -n kafka-kerberos-demo --timeout=120s
kubectl wait --for=condition=ready pod -l app=kafka -n kafka-kerberos-demo --timeout=120s
```

### 2. Create KEDA Authentication

```bash
kubectl apply -f 03-kerberos-secret.yaml
kubectl apply -f 04-trigger-authentication.yaml
```

### 3. Deploy the Consumer and ScaledObject

```bash
kubectl apply -f 05-consumer-deployment.yaml
kubectl apply -f 06-scaledobject.yaml
```

### 4. Test Scaling

Produce messages to trigger scaling:

```bash
kubectl apply -f 07-test-producer.yaml
```

Watch the consumer deployment scale:

```bash
kubectl get deployment kafka-consumer -n kafka-kerberos-demo --watch
```

### 5. Cleanup

```bash
kubectl delete namespace kafka-kerberos-demo
```

## Files Description

- `01-kdc-deployment.yaml` - Kerberos KDC with initialization
- `02-kafka-deployment.yaml` - Kafka broker with GSSAPI authentication
- `03-kerberos-secret.yaml` - Kerberos credentials (password-based example)
- `03-kerberos-secret-keytab.yaml` - Alternative keytab-based authentication
- `04-trigger-authentication.yaml` - KEDA TriggerAuthentication resource
- `05-consumer-deployment.yaml` - Sample Kafka consumer deployment
- `06-scaledobject.yaml` - KEDA ScaledObject configuration
- `07-test-producer.yaml` - Job to produce test messages

```
         │ Authenticates

```

## Kerberos Configuration Details

### Realm
- Name: `KEDA.LOCAL`
- KDC: `kdc.kafka-kerberos-demo.svc.cluster.local:88`

### Principals
- Kafka Broker: `kafka/kafka.kafka-kerberos-demo.svc.cluster.local@KEDA.LOCAL`
- Test User (password): `testuser@KEDA.LOCAL` (password: `testpassword`)
- Test User (keytab): `keytabuser@KEDA.LOCAL`

### Keytab Files
Keytabs are automatically generated by the KDC initialization script and stored in:
- Kafka keytab: `/keytabs/kafka.keytab` (inside KDC and Kafka pods)
- User keytab: `/keytabs/keytabuser.keytab` (inside KDC pod)

## Customization

### Using Your Own KDC

If you have an existing Kerberos KDC, skip `01-kdc-deployment.yaml` and update:

1. `02-kafka-deployment.yaml` - Update KDC hostname in krb5.conf
2. `03-kerberos-secret.yaml` - Update realm and KDC configuration
3. Ensure network connectivity from your cluster to the KDC

### Using Keytab Authentication

Replace `03-kerberos-secret.yaml` with `03-kerberos-secret-keytab.yaml` and update:
1. Generate a keytab for your service principal
2. Base64-encode the keytab: `base64 < your.keytab`
3. Update the `keytab` field in the Secret

### Changing Kafka Version

Update the image in `02-kafka-deployment.yaml`:
```yaml
image: confluentinc/cp-kafka:7.5.0  # Change version as needed
```

## Troubleshooting

### KDC Not Starting

Check KDC logs:
```bash
kubectl logs -n kafka-kerberos-demo -l app=kdc
```

Common issues:
- Database creation failed - check permissions
- Port 88 already in use - check for conflicting services

### Kafka Authentication Failing

Check Kafka logs:
```bash
kubectl logs -n kafka-kerberos-demo -l app=kafka -c kafka
```

Common issues:
- Clock skew - ensure time synchronization
- Wrong principal name - verify principal exists in KDC
- KDC not reachable - check network connectivity

### KEDA Not Scaling

Check KEDA operator logs:
```bash
kubectl logs -n keda deployment/keda-operator
```

Check ScaledObject status:
```bash
kubectl describe scaledobject kafka-scaledobject -n kafka-kerberos-demo
```

Common issues:
- Authentication failed - verify credentials in Secret
- Topic doesn't exist - check Kafka topic creation
- Consumer group has no lag - produce test messages

## Production Considerations

This example is for **demonstration purposes only**. For production:

1. **Use Keytab Authentication**: Replace password-based auth with keytabs
2. **Secure Secrets**: Enable encryption at rest for Kubernetes Secrets
3. **Enable TLS**: Add TLS encryption in addition to Kerberos
4. **High Availability**: Deploy multiple Kafka brokers
5. **Resource Limits**: Set appropriate CPU/memory limits
6. **Monitoring**: Add Prometheus metrics and alerts
7. **Backup Keytabs**: Store keytabs securely in a secret management system
8. **Regular Rotation**: Implement keytab rotation procedures
